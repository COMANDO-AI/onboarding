Hoy el test está vivo en comando-ai.com/readiness, pero no se guarda ni un lead: el mail y el CRM se saltean en silencio. Es chico, se puede verificar y te hace tocar todo lo que importa: secretos, Notion, Resend, variables de entorno.

01Parte 1 · Gate 1

La Connection,
con op

En jm-os, apenas aceptás la invitación al vault.

  1. Confirmá de quién es la cuenta. Instagram va con tu cuenta personal. Si alguna vez la querés apuntar a una cuenta de COMANDO, frenás y lo hablás con Mariano: un token que publica como la empresa es comunicación externa.
  2. El token va al vault, nunca al disco. En jm-os solo vive la referencia op://…; el valor lo inyecta op run o op read.
  3. Probala. Un TL_ que lea algo real de tu cuenta (tus últimas publicaciones) con el token inyectado. Si devuelve datos, está autenticada.
  4. Armá la rutina de renovación. El token largo de Meta vence a los 60 días y, si nadie lo renueva, la Connection se rompe sin avisar. Renovación cada ~50 días como rutina de cadencia. Eso también cumple el criterio de rutina del gate.
  5. Cerrá el gate por escrito. Los cinco criterios del onboarding, uno por uno, con su evidencia en el pulse de jm-os.
Terminal · comprobar op
op whoami
op vault list

03Parte 2 · Armar

Notion, Resend
y el vault

La base de leads, en tu Notion

De prueba: la tuya, no la de COMANDO. Con las propiedades que pide crm.ts, con estos nombres exactos:

PropiedadTipo
NameTítulo
Email · Company · Role · Industry · SizeTexto (Email puede ser tipo email)
Source · BandSelect
Readiness IndexNúmero
Archetype · SummaryTexto

Creá una integración interna de Notion y compartí la base con ella. Eso te da el token y el ID de la base.

Resend, con tu mail

Abrí una cuenta en resend.com. Sin dominio verificado, Resend solo te deja mandar desde onboarding@resend.dev a tu propia dirección. Para esta prueba alcanza.

Todo secreto, al vault

El token de Notion, el ID de la base, la API key de Resend y la key de Anthropic que te pasa Mariano van a tu vault. En la carpeta del sitio, un archivo con solo referencias, nunca valores. El nombre .env.op.local ya está ignorado por git.

.env.op.local · solo referencias
ANTHROPIC_API_KEY=op://jm-os/anthropic/credential
NOTION_TOKEN=op://jm-os/notion-leads/credential
NOTION_LEADS_DB_ID=op://jm-os/notion-leads/db_id
RESEND_API_KEY=op://jm-os/resend/credential
RESEND_FROM=onboarding@resend.dev
READINESS_NOTIFY_EMAIL=martin.echeverry@comando.live

Los nombres de vault e ítem son un ejemplo: usá los tuyos.

04Parte 2 · Probar

El test entero,
de punta a punta

Terminal
op run --env-file=.env.op.local -- npm run dev
  1. Abrí localhost en la ruta /readiness (el puerto lo imprime la Terminal).
  2. Hacé el test completo con una empresa inventada y tu mail.
  3. Comprobáuna página nueva en tu base de Notion, con el índice, la banda y el arquetipo.
  4. Comprobáel mail del reporte en tu bandeja.
  5. Si algo no llega, la Terminal dice por qué: [crm] skipped o [email] con el motivo.
Ojo con el costo

Cada test completo son 13 turnos de Opus más una llamada de puntaje. Hacé las corridas que necesites, no más, y anotá cuántas hiciste.
